# VDV453-VIS Data Source

## Purpose

The VDV453 data source imports vehicle positions from a VDV453-VIS producer. It is registered under the type `vdv453`. General data source behavior, execution modes, and record envelope are described in [datasources.md](datasources.md); this document only covers the VDV453-specific parts. It mirrors the structure of the VDV454 data source, see [vdv454.md](vdv454.md).

The transformation of VIS messages into vehicle-position records is specified in [transformers/vdv453_31_vehicle_positions_transformer.md](transformers/vdv453_31_vehicle_positions_transformer.md).

## Configuration

| Field | Type | Required | Description |
|---|---|---|---|
| `endpoint` | url | yes | URL of the producer. |
| `subscriberref` | text | yes | Identifier of this system, used as requestor and subscriber reference. |
| `producerref` | text | yes | Identifier of the VDV453 producer system. |
| `dialect` | enum | yes | VDV453 implementation variant. Currently only `vdv453_31` (label `VDV453-VIS 3.1`). |
| `filter` | taglist | no | Operator and line filters passed to the transformer. |

`endpoint`, `subscriberref`, and `producerref` are optional for event-based sources, which receive their payload through the push API. There is no consumer endpoint: the VIS subscription is configured at the producer, which delivers to the consumer address agreed there. The stop-handling options of the VDV454 data source do not exist because vehicle positions do not go through the stop propagation.

The dialect is the selector of the transformer, so further VDV453 versions can be added as new dialects.

## Execution

| Execution type | Behavior |
|---|---|
| `event_based` | Parses the XML payload supplied through the public push API. |
| `subscription_based` | Receives the payload through the internal push endpoint after the subscription service has started the subscription. |

Active fetching is not supported: `_fetch_records` raises `NotImplementedError`, so time-based execution is not usable.

The parsed XML root is passed to the transformer as `{"root": root, "source_name": ...}`. The result is returned as the `vehicle_positions` envelope with the transformer runtime in `_transform_runtime_ms`. A failing transformation is logged as request log entry with status 500 and raised as `ValueError`.

The VIS feed is differential, so the data source must be run with differential updates enabled, see [differential-incremental.md](differential-incremental.md).

## Subscription Parameters

`Vdv453Datasource` inherits `SubscriptionDatasourceBase` and implements `get_subscription_params()` as a best-effort mapping with the parameter names of the SIRI subscription service (see [siricomservice.md](siricomservice.md)):

| Parameter | Value | VDV453 equivalent |
|---|---|---|
| `provider_url` | `endpoint` | producer address |
| `profile` / `version` / `service` | `de-vdv` / `3.1` / `VM` | SIRI service code (the SIRI consumer always uses SIRI codes); VDV service `VIS` (`AboVIS`) |
| `delivery_mode` | `fetched` | - |
| `requestor_ref`, `subscriber_ref` | `subscriberref` | `Sender` |
| `producer_ref` | `producerref` | producer identifier |
| `initial_termination_time` | `2999-12-31T23:59:00Z` | `VerfallZst` |
| `incremental_updates` | `true` | - |
| `filters` | operators and lines from `filter` | `LinienFilter` |
| `heartbeat` | enabled, 180 s timeout | - |
| `logging` | `false` | - |

No `consumer_address` is provided.
