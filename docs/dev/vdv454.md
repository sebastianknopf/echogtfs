# VDV454-AUS Data Source

## Purpose

The VDV454 data source imports trip updates from a VDV454-AUS producer. It is registered under the type `vdv454`. General data source behavior, execution modes, and record envelope are described in [datasources.md](datasources.md); this document only covers the VDV454-specific parts.

The transformation of AUS messages into trip-update records is specified in [transformers/vdv454_31_trip_updates_transformer.md](transformers/vdv454_31_trip_updates_transformer.md).

## Configuration

| Field | Type | Required | Description |
|---|---|---|---|
| `endpoint` | url | yes | URL of the producer. |
| `subscriberref` | text | yes | Identifier of this system, used as requestor and subscriber reference. |
| `producerref` | text | yes | Identifier of the VDV454 producer system. |
| `dialect` | enum | yes | VDV454 implementation variant. Currently only `vdv454_31` (label `VDV454-AUS 3.1`). |
| `treat_unexpected_stop_as_added_stop` | boolean | yes | Defaults to `false`. Consumed by the stop propagation, see [stop-propagation.md](stop-propagation.md). |
| `treat_missing_stop_as_canceled_stop` | boolean | yes | Defaults to `false`. Consumed by the stop propagation. |
| `incorrect_stop_id_handling` | enum | yes | `IGNORE` (default) or `FIX_TO_NOMINAL_STOP_ID`. |
| `filter` | taglist | no | Operator and line filters passed to the transformer. |

`endpoint`, `subscriberref` and `producerref` are optional for event-based sources, which receive their payload through the push API. Unlike the SIRI data sources, there is no consumer endpoint: the VDV454 subscription is configured at the producer, which delivers to the consumer address agreed there. The endpoint is only used as `provider_url` of the subscription; no placeholders are resolved.

`DatasourceBase` treats a dialect as the selector of the transformer. The dialect value is a stable identifier so that further VDV454 versions can be added as new dialects with their own transformer.

## Execution

| Execution type | Behavior |
|---|---|
| `event_based` | Parses the XML payload supplied through the public push API. |
| `subscription_based` | Receives the payload through the internal push endpoint after the subscription service has started the subscription. |

Active fetching is not supported: `_fetch_records` raises `NotImplementedError`, so time-based execution is not usable.

The parsed XML root is passed to the transformer as `{"root": root, "source_name": ...}`. The result is returned as the `trip_updates` envelope with the transformer runtime in `_transform_runtime_ms`. A failing transformation is logged as request log entry with status 500 and raised as `ValueError`.

VDV454 AUS is a differential feed, so the data source should be run with differential updates enabled, see [differential-incremental.md](differential-incremental.md).

## Subscription Parameters

`Vdv454Datasource` inherits `SubscriptionDatasourceBase` and implements `get_subscription_params()` as a best-effort mapping, using the parameter names of the SIRI subscription service (see [siricomservice.md](siricomservice.md)):

| Parameter | Value | VDV454 equivalent |
|---|---|---|
| `provider_url` | `endpoint` | producer address |
| `profile` / `version` / `service` | `vdv454` / `3.1` / `AUS` | service `AUS` (`AboAUS`) |
| `delivery_mode` | `direct` | - |
| `requestor_ref`, `subscriber_ref` | `subscriberref` | `Sender` |
| `producer_ref` | `producerref` | producer identifier |
| `preview_interval` | `PT2H` | `Vorschauzeit` |
| `initial_termination_time` | `2999-12-31T23:59:00Z` | `VerfallZst` |
| `incremental_updates` | `true` | `NurAktualisierung` |
| `change_before_updates` | `PT30S` | `Hysterese` |
| `heartbeat` | enabled, 180 s timeout | - |
| `logging` | `false` | - |

No `consumer_address` is provided.

## Open Points

- The current subscription service targets SIRI. Whether it can create and maintain VDV454 subscriptions with these parameters (including `producer_ref`) is not verified.
- `Vorschauzeit` of 2 hours matches the trip window of the transformer; the value range accepted by producers is subject to the VDV454 specification (30 to 180 minutes).
